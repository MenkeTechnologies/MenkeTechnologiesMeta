zmax-gui-core ships the embeddable webview GUI surface for zmax-gui: the MacVim-style menu/dialog/shortcut layer that drives the zmax CLI editor (a Helix fork) through its embedded PTY. It is webui-only — no Rust crate, no IPC of its own — so the standalone app and any embedding host serve identical assets.

Action map → PTY

Every menu item, ⌘-shortcut and dialog action is bridged to the editor by writing bytes into the PTY. Esc is sent on its own and the rest follows after a short delay (longer than the editor's esc-disambiguation window), so the editor treats Esc as a discrete keypress rather than parsing ESC<byte> as Alt+<byte>. When editor-state.js has a trusted reading that says normal mode, the Esc and the wait are skipped; every outbound burst marks the reading stale until the next observed statusline.

// run an ex-command from any mode: Esc -> :cmd -> Enter
afterEsc(":w\r");        // Save
afterEsc(":q\r");        // Quit
ptyWrite("\x13");        // raw control byte for a keymap-bound action

Verification

node --test webui/*.test.cjs exercises the menu→PTY bridge, the state reconstruction and the HUD headlessly. This repo has no package.json; zmax-gui's test:js / scripts/test.sh discover these suites through scripts/run-js-tests.mjs, so the single source is tested in place.
