What zstation is

zstation is a from-scratch port of the defunct station.app: one window that arranges your web apps as Trello-like tiles, each in its own isolated session. The desktop shell is a Tauri v2 application with a cyberpunk HUD front-end. The board logic is factored out into a separate, embeddable engine, zstation-core, so the same engine can be reused inside the other MenkeTechnologies GUI apps without dragging GUI or platform dependencies into them. It is a paid product, created by MenkeTechnologies.

Native isolated-webview host

Real per-service session isolation requires native, separately-partitioned webviews (an iframe cannot isolate a login: services forbid framing and iframes share the cookie jar). The host places one child webview per tile via Tauri v2 WebviewWindow::add_child and isolates each by partition — data_store_identifier on macOS/iOS, data_directory on Windows. The mountable view reaches these commands through frontend/station-host.js; they live in app/src-tauri/src/station_webview.rs unless another file is named.

Per-tile settings and the workspace lock

A web tile's Tile settings (context menu, ⌘K palette, Tile ▸ Tile Settings…) set where new-window links open, the tile's own User-Agent (applied by reopening the webview; the session store is untouched) and an auto-reload interval that skips sleeping, minimised or in-use tiles. All three are engine Tile fields validated by tile.update. Lock workspace (⌘⇧L, Tools ▸ Lock Workspace) parks every tile webview behind a PIN pad; the PIN is held by the engine (lock.*) as a salted, stretched SHA-256 digest, with an idle auto-lock delay and lock-on-launch set from Tools ▸ Lock Settings…. A lock or unlock is broadcast on zst://lock so every pop-out window locks together. It is a privacy screen and does not encrypt the session stores.

GUI baseline

zstation consumes the 10-point MenkeTechnologies family GUI contract from the shared submodules: ⌘K command palette, Stryke Hooks editor, embedded terminal, shared cyberpunk theme, tab bar + tile dashboard, top-left logo, fuzzy filters, sortable/resizable tables, clip-engine arrangement grid, and a multi-pane file browser — wired in the app shell rather than reimplemented per app.

Verification

pnpm test runs the app-repo JS suites under tests/ (the served build and the submodule seams: palette ids, i18n staging, the Drift grid domain, overlay tokens) and the Rust tests of both the host crate and zstation-core. The embeddable engine carries its own in-source unit tests plus headless Node suites for the mountable view (see the zstation-core report). The pure engine runs without network access and is intended to pass identically in headless CI.
